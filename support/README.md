# 지원사업 소식 자동 수집

운영 흐름: GitHub Actions → 공식 공고/첨부 조사 → `support-data` 브랜치 저장 → 워크보드 상단 한 줄.
이 폴더에는 회사 계정, PIN, 근태, 결재, 인증키를 저장하지 않는다. 수집 대상과 결과는 공개 공고다.

## 예약

- 매일 한국시간 05:13, 07:13에 실행한다. PC가 꺼져 있어도 동작한다.
- 오전 8시 전 조사를 마친 게시본은 당일 08:30, 그 이후에 만든 게시본은 다음 날 08:30부터 화면에 표시한다.
- 예약 시각까지 이전 게시본을 유지한다. 화면은 30초마다 공개시각을 대조하고 자료는 5분마다 갱신한다.
- 공개시각 비교에는 기기 시계를 사용하며, 응답에서 서버 시각을 읽을 수 있으면 차이를 보정한다. 관련성이 높은 접수 공고 최대 5건을 한 줄에서 순환하며, 나머지 선별 공고는 전체 보기에서 찾을 수 있다.
- GitHub 예약은 지연될 수 있다. 원본 조회 실패·지난 게시본·초기 역수집 진행 상황은 화면의 ‘조사 상태’에 표시한다. 08:00까지 완료되었다고 무조건 주장하지 않는다.
- 조회에 모두 실패하면 기존 게시본을 새 자료처럼 다시 게시하지 않는다. 이전 성공 자료와 실패 상태를 남긴다.

## 조사 범위와 한계

기업마당, K-Startup, 예술경영지원센터, 대구문화예술진흥원, 한국문화예술위원회, 대구테크노파크, DASH, 대구디지털혁신진흥원. 기업마당의 주관기관 원문 링크도 따라가 본문과 첨부를 추가 확인한다.

PDF, HWP, HWPX와 압축 안의 문서를 읽는다. 서버에는 한글 OCR도 설치해 이미지형 PDF를 보완한다. 암호 문서·이미지 인식 실패·연결 오류·크기 제한 초과 등은 미확인으로 남긴다. 모든 문서를 사람이 판독한 것과 같지 않다.

본문·첨부의 조건을 규칙으로 발췌하며 AI가 신청 가능 여부를 확정하지 않는다. 업종/지역 키워드가 맞지 않아도 수집 자체에서 버리지 않는다. 관련성이 높은 대구·주력 분야 공고를 먼저 보여 주고, 모든 게시 공고는 검색·분야 필터·더 보기로 접근한다. 자부담, 제외 조건, 마감 시각을 찾지 못하면 ‘없음’으로 단정하지 않는다.

최신 목록 최대 25페이지를 매번 겹쳐 읽고, 이전 페이지는 기관별 진행 위치를 보존하며 계속 대조한다. 한 차례 끝까지 도달하면 처음부터 다시 대조한다. 진행/미확인 공고는 매일, 종료 공고는 7그룹으로 나누어 주간 재조회한다. 목록/본문/첨부 변경을 해시와 이력으로 보존한다. 실행 시간이 끝나면 남은 공고를 다음 실행에서 이어간다. 초기 역수집 완료 전에는 완료 표시를 하지 않는다.

기관별 게시판 구조 변경이나 사이트 차단으로 누락이 생길 수 있다. 사이트 전부를 빠짐없이 읽었다고 보장하지 않으며, 수집 상태와 마지막 성공 시각을 반드시 함께 확인한다. 국가·지자체 모든 기관의 직접 게시판을 연결한 것은 아니다.

## 저장과 복구

- `state.json`: 기관별 진행 위치, 재시도 목록
- `records/*.json`: 공고별 조건 발췌·첨부 해시·원문 확인·변경 이력
- `feed.json`: 최근 3개의 게시본과 최신 조사 상태
- `runs/*.json`: 실행별 기관 상태/건수

기록 파일에는 공고 원본을 임의 수정하지 않고 조사 내용을 보관한다. 본문이 삭제되거나 연결이 실패해도 마지막 성공 내용을 보존하고 미확인 표시한다. 소식 저장 브랜치는 업무 저장 서버와 분리되어 있다.

수동 실행: GitHub ‘지원사업 매일 조사’ → Run workflow. 장애 해결 후 같은 작업을 다시 실행하면 대기 목록부터 이어진다. 수집 중복 실행은 직렬화된다. 서비스 중단은 해당 workflow를 Disable하며, 기존 업무 자료에는 영향이 없다.

로컬 시험: `python -m unittest discover -s support/tests -v`. 자료를 공개하기 전에 비밀값·회사 내부 정보가 들어 있지 않은지 확인한다.

## 2026-10-08 노출 선별 정책 2

수집 원본과 화면 게시를 분리한다. `relevance.py`는 제목·신청 대상의 근거로 철거·인테리어, 부동산·경영 컨설팅, 현대무용·공연기획, 부동산 앱·플랫폼에 분류한다. 일반 기업 대상 자금·사업화 지원도 후보로 남기되 의료·제조·수출 등 다른 산업 전용, 타 지역 지정, 음악·미술 등 다른 예술, 일반 교육·설명회·결과 발표는 노출하지 않는다. 본문 메뉴에 관련 단어가 있다는 이유만으로 포함하지 않는다. 자동 선별은 자격 확정이 아니다.

노출 건수 하한은 없다. 관련 공고가 없으면 빈 분야를 만들거나 무관한 공고로 채우지 않는다. 모든 원본과 재조사는 유지한다. 초기 12건씩 보여 주고 검색·더 보기로 선별된 전체 자료를 볼 수 있다. 선별 정책이 없는 예전 캐시 공고는 표시하지 않는다.

기존 게시본에 새 기준만 적용할 때 workflow_dispatch의 `refilter_only=true`를 사용한다. 기존 조사·공개 시각을 유지하여 아직 공개되지 않은 자료를 일찍 공개하지 않는다. 기존 feed의 선별만 다시 하므로 이전에 제외된 자료의 복원은 다음 정규 전체 catalog 선별에서 이루어진다.
